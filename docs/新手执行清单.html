M1：让一只机器人手在电脑里正确动起来

**输入：**一套完整机器人模型，包含 URDF 及其引用的网格资源。

操作：

  1. 读取 robots/README.md，建立 robots/<手型名>/。
  2. 记录模型仓库、commit、许可证与资源路径，原始模型留一份。
  3. 选择和后续基线匹配的显示/运动学环境。按官方说明建独立环境并记录版本；未决定环境前不同时安装多套仿真器。
  4. 加载模型，给每个可控关节一次小范围变化，观察是否是预期手指与方向。
  5. 打印关节名与角度，计算 FK，标出指尖坐标。核对米/毫米、弧度/角度。
  6. 保存加载画面、动作演示与检查记录到 复现/model_check/。

输出：复现/model_check/复现报告.md，包含模型能加载、资源完整、顺序正确、限位正确和指尖定义。

**验收：**不是“窗口打开了”，而是“改变指定关节时对应手指按预期运动，FK 与画面一致”。若模型没有驱动信息，明确只完成运动学检查。

M2：先复现简单方法和已有基线

**输入：**固定的少量离线手部样本及 M1 的机器人模型。

操作：

  1. 建立一个小的 smoke 样本集，用张手、弯指与捏合等姿态排查接口；它只用于调试。
  2. 核对关键点顺序、左右手、腕部坐标、单位，记录到 dataset.md。
  3. 在 复现/<基线名>/ 内放外部代码或引用其位置，记录来源版本，使用独立环境。
  4. 跑简单方向/尺度归一化，条件允许时再跑姿态角迁移。
  5. 按 dex-retargeting 官方例子 选择与你模型匹配的模式，保存输入、配置和输出。
  6. 用 FK 检查实际指尖，而不是只看输出数组长度是否正确。
  7. 建立正式的独立验证/测试名单，冻结测评规则；smoke 样本不充当正式泛化证据。
  8. 将完成的运行追加到 experiment/results.md，失败也记。

**输出：**基线复现报告、参数配置、环境记录、样本清单和初始测评。

**验收：**另一个窗口按照报告中的确切命令可重跑，并取得相同口径的输出。如果论文数字与本地数据不可比较，明确记录差异，不强行声称复现原论文结果。

M3：实现跨尺寸网络

**输入：**源形状/动作、目标形状与参考动作，基线与正式划分已固定。

操作：

  1. 从合法获得的 MANO 模型或明确的骨架开始，先可视化一个形状和一个动作。
  2. 生成/整理少量配对样本，检查形状变化是否合理，记录标签是姿态复制还是任务约束优化。
  3. 固定训练、验证、测试的形状/操作者与序列 ID。
  4. 先训练小型 MLP 候选；保存输入字段、旋转约定、配置、种子、训练日志与权重。
  5. 做未见形状测试，与简单方法比较；同时检查不同动作是否被网络区分。
  6. 保存目标 R 的关键点或姿态，并记录哪些样本不能保持捏合。

输出：experiment/<版本名>/ 内的计划、配置、日志、指标与失败样例。

**验收：**在相同测试名单上比较，而不是训练误差下降就过关。若网络无新增收益，回到动作定义与标签构造，先别加更大模型。

M4：实现机构约束与欠驱动映射

**输入：**第一阶段的目标动作、完整机构/驱动描述。

操作：

  1. 先用一个明确的固定耦合教学模型区分 u 与 q；例子不能当作真实手的驱动参数。
  2. 根据真实资料整理独立控制量、范围、耦合关系与 FK 链。
  3. 实现可行空间中的优化参考解，保存收敛状态与不可达目标。
  4. 训练机构条件映射候选，输出执行器指令，并通过机构模型恢复关节状态。
  5. 比较投影前后误差与违规；分别报告几何匹配和任务功能。
  6. 缺少真实驱动模型时标明当前只在简化假设下验证。

**验收：**输出符合真实可控制量，且耦合/限位约束被核查。给每个关节输出一个漂亮角度数组不算完成欠驱动适配。

M6：加上摄像头与真实控制

先做离线视频重放，再做实时视觉输入，最后在具备实际设备接口时开展真机验证。分别记录视觉估计、两个映射阶段和控制接口的耗时。视觉帧丢失时的保持/停止行为也要明确实现和测试。

**验收：**记录端到端稳定性、指令与关节回读以及实际任务结果。仿真成功与真机成功分别写，不能互相代替。
