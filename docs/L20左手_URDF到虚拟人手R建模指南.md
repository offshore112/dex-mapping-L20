# L20 左手：从 URDF 建立 MANO 虚拟人手 R

日期：2026-10-16（Asia/Shanghai）。状态：**来源核查、L20 FK、仿真参考点和 v5 静态 MANO-R 拟合已完成；动态基线与训练未运行。**

用户已提供 L20 左手 URDF 的官方仓库入口及本地 URDF/网格、MANO_LEFT.pkl。独立环境与 MANO 加载检查、L20 文件层面 FK、v4 点集和 v5 静态拟合已完成，见 [环境使用说明](MANO与L20独立环境使用说明.md)、[FK 检查说明](L20正运动学坐标与联动检查.md) 和 [v5 拟合报告](../experiment/v5_MANO-R拟合/fit_report.md)；硬件批次、真实尺度、SDK 与动态几何验证仍待完成。本指南延续 [两阶段研究主线](研究思路与新手指南.md)：先跨人手尺寸，再处理目标机器人的驱动与耦合。URDF→R 是目标几何准备模块。

**用户已明确的共享目标手定义：**固定 L20 时，不同操作者共用同一只目标几何虚拟手 `R_L20`；不是为每个操作者单独拟合一只 `R`。因此所有操作者共享固定的 `beta_R`、尺度、对齐、参考姿态和对应点语义，第一阶段只输出各自的动作状态。若更换目标机器人，才按机器人生成相应的 `R_j`。论文 Qin 等人的 per-operator 定制手可参考其程序化构造方法，但不能改变这个接口定义。

## 1. 可以建立什么

可以尝试用 L20 的几何信息，拟合一个尺寸、指节比例和指根布局尽量接近它的 MANO 虚拟人手 R。拟合结果需要有逐部位残差；能否满足后续映射要求，必须实际运行后判断。

URDF 与 MANO 是两套不同的模型，不能直接按字段转换：URDF 描述机器人刚性部件与运动连接；MANO 的形状空间来自人手扫描，具有固定的人手拓扑与统计相关性。MANO 的 β 不能逐项任意指定每根指骨、关节轴或驱动耦合。

把 R 分为两个部分：

- **固定几何**：拟合得到的 β_R、全局尺度 s、选定的关键点规则和与机器人掌部坐标系的对齐。每个目标机器人/模型版本固定一套。
- **变化动作**：每一帧的 θ_R(t)，由第一阶段产生。不要每帧重新拟合 β_R，否则机器人几何会随动作漂移。

一个候选表达是 `X_R(t) = s · A · K(MANO_left(β_R, θ_R(t))) + b`。K 提取事先定义的对应点；A 是三维旋转矩阵；b 是坐标平移；s 是额外的正尺度。尺度、旋转、平移不属于 MANO 形状参数 β。

R 的动作空间保留虚拟人手的能力。机器人限位、真实驱动与 `mimic` 留给第二阶段，不在 R 里预先强行施加 L20 的五条联动约束。

## 2. 这份 L20 URDF 已核查到的内容

来源：[L20 左手目录](https://github.com/linker-bot/linkerhand-urdf/tree/main/L20/left)、[原始 URDF](https://raw.githubusercontent.com/linker-bot/linkerhand-urdf/main/L20/left/linkerhand_l20_left.urdf)。读取的是在线 main 内容，**尚未锁定 commit，也未与用户本地文件对比**。统计来自对网页返回的完整 1204 行进行标签解析，不是仿真测试。

| 项目 | 文件中的内容 | 含义 |
|---|---|---|
| robot 名称 | linkerhand_l20_left | 左手模型 |
| 根 link | hand_base_link | 机器人基座参考系，不能直接当作 MANO 腕部解剖中心 |
| link | 22 个，名称无重复 | 机器人刚性部件，不等于 MANO 骨架节点 |
| joint | 21 个，全部 revolute，名称无重复 | 全部转动关节坐标 |
| mimic | 5 条 | 四指 DIP 从动于 PIP；拇指 IP 从动于 MCP |
| 独立运动学坐标 | 16 个 | 对这份树模型施加五条 mimic 后的数量；不等于已验证 SDK 控制接口 |
| transmission / ros2_control | 未发现 | 缺少完整的执行器接口与命令到角度转换 |
| 单独命名的 tip link | 未发现 | 五个指尖初始局部点已由 v4 网格端盖规则定义，接触语义仍待验证 |
| 网格引用 | meshes/*.STL，相对路径 | 加载显示模型时必须保留 URDF 与 meshes 的相对目录结构 |

四指的简化链：`hand_base_link → *_metacarpals → *_proximal → *_middle → *_distal`。对应关节依次是 `*_mcp_roll → *_mcp_pitch → *_pip → *_dip`，其中 `*` 是 index、middle、ring、pinky。

拇指链不同：`hand_base_link → thumb_metacarpals_base2 → thumb_metacarpals_base1 → thumb_metacarpals → thumb_proximal → thumb_distal`。关节依次是 `thumb_cmc_yaw → thumb_cmc_roll → thumb_cmc_pitch → thumb_mcp → thumb_ip`。三个 CMC 关节原点有空间偏移，不能把它们的名称当成与 MANO 单一基部节点严格重合的证据。

文件写明：

```text
q_index_dip  = 0.8917 · q_index_pip
q_middle_dip = 0.8917 · q_middle_pip
q_ring_dip   = 0.8917 · q_ring_pip
q_pinky_dip  = 0.8917 · q_pinky_pip
q_thumb_ip   = 1.1619 · q_thumb_mcp
```

全部 offset 为 0。这是**该 URDF 的固定线性近似**，并非对真实连杆在全部工况下准确性的验证。所选 FK/仿真库是否自动处理 mimic，也需要显式检查。

[厂商 L20 页面](https://www.linkerbot.cn/details/LinkerHandL20/)标注 16 个主动自由度与 5 个被动自由度；[厂商 ROS SDK](https://github.com/linker-bot/linkerhand-ros-sdk#position-to-finger-joint-mapping-table)的 L20 数组有 20 个槽位，其中 4 个为 Reserved。两者与本文件的数量结构相容，但 **SDK 槽位顺序、单位、零点、方向、硬件版本与 URDF 的具体对应仍待核查**。L20 与 L20 Lite 也不能混用。

## 3. 第一步：准备两套模型，先确定接口

计划输入：

1. 用户现有的 `linkerhand_l20_left.urdf` 与完整 `meshes/`；保留原件并记录来源 commit 与文件哈希。
2. 合法获得的 `MANO_LEFT.pkl` 与其模型版本。模型需从 [MANO 官方入口](https://mano.is.tue.mpg.de/)注册、同意相应许可后获取；安装 Python 包不自动带来模型文件。
3. 一套能够计算机器人正运动学（FK）的环境，以及可微的 MANO 实现。候选为 PyTorch 配合作者维护的 [smplx](https://github.com/vchoutas/smplx)；这是拟实施工具选择，当前未安装项目环境。

只算关节原点的 FK 可以先不加载网格；掌部外形、末节长度与指尖接触点需要网格或额外几何资料。

候选 MANO 设置：`is_rhand=False`、`use_pca=False`、`flat_hand_mean=True`、`num_betas=10`。其中前者固定左手；后两者避免把零姿态输入误解为统计平均弯曲姿态。β 的实际可用维数仍须检查模型文件。

作者实现的 MANO 定义 15 个局部手关节，完整轴角表示通常有 45 个局部姿态参数，另有 3 个整体旋转参数。常用的 21 点是 16 个骨架点再加 5 个指尖点，但具体输出顺序与是否自动追加指尖必须按实现确认。[实现依据](https://github.com/vchoutas/smplx/blob/main/smplx/body_models.py)

## 4. 第二步：从机器人提取有语义的几何点

### 4.1 先固定单位、坐标和参考姿态

计算采用米与弧度；报告距离时再转换为毫米。核对 STL 尺度是否与 URDF 一致，不能因为 STL 文件没有单位字段就默认其尺寸正确。

先用所有独立关节角为零作为**文件参考姿态**，按 mimic 补全从动关节。零姿态是否适合作为张手，需要看模型；尤其拇指有非零固定 rpy，不可把全部 rpy 清零。若选其他参考姿态，保存确切 q_ref。

URDF 的关节位置相对父 link。对每个关节沿整条链计算：

```text
T_child(q) = T_parent(q) · T_origin(xyz, rpy) · T_axis_rotation(q_joint)
```

关节轴是在关节局部系定义的。不要直接把各关节 `<origin xyz>` 堆成全局点，也不要用 `<inertial origin>` 的质心作为关节中心。

定义虚拟腕部位置，并保存其相对 `hand_base_link` 的变换。本轮仿真暂采用 `hand_base_link.STL` 底部安装平面的面积中心作为 `wrist_ref`，完整点集见 [v4 点集](../robots/L20_left/l20_r_reference_points_v4.json)；这不是已验证的解剖腕点。掌面方向可由已选指根点建立；使用一致的右手坐标系，轴方向写清。MANO 与机器人必须是同一侧，避免通过镜像反射掩盖错误。

### 4.2 计划的 21 点对应

下表是候选语义对应，必须在叠图后确认。机器人机械关节中心与人体关节中心只作近似对应。

| 点组 | 机器人取点规则 | MANO 一侧 |
|---|---|---|
| 腕部 1 点 | 选定的腕/掌基准点，保存局部坐标 | 腕部骨架点 |
| 四指各 4 点 | `*_mcp_pitch`、`*_pip`、`*_dip` 的 FK 关节原点，再加 `*_distal` 内定义的指尖点 | 掌指关节 MCP、近端指间关节 PIP、远端指间关节 DIP、指尖 |
| 拇指 4 点 | 暂以 `thumb_cmc_pitch` 原点作为基部候选，接 `thumb_mcp`、`thumb_ip` 原点与 distal 内指尖 | 基部 CMC、MCP、IP、指尖 |

四指 `mcp_roll` 与 `mcp_pitch` 原点相距约 16.77 mm，所以不能把这两个机械轴都强塞进一个人体 MCP 点。拇指基部多轴且有偏移，选 `cmc_pitch` 是候选几何代理；若拟合或动作误差集中于这里，需要重新评估代理或改用更多辅助点。

在每个末节 STL 上标注一个约定明确的末端点。本轮仿真将 `*_distal.STL` 局部 `+z` 端 0.5 mm 带宽内三角面的面积加权中心作为 `*_tip`，保存为 `local_xyz_m`，再由 FK 转成掌部坐标。该点是远端端盖中心，不等同于真实指腹接触中心；不要把 distal link 原点或未经检查的包围盒极值直接当指尖。

**提取结果已保存为** [`l20_r_reference_points_v4.json`](../robots/L20_left/l20_r_reference_points_v4.json)：点名、所属 link、局部点、URDF 零姿态下的根坐标、单位、坐标系、选择规则和来源哈希均有记录。它是仿真初始几何约定，不是硬件标定。

### 4.3 一个已能从关节原点得到的长度例子

食指 MCP_pitch→PIP 的中心距为：

```text
sqrt((-0.0041945524)^2 + 0^2 + (0.0448194356)^2)
≈ 0.0450153 m = 45.02 mm
```

PIP→DIP 中心距约 31.82 mm。这是对当前文件坐标的算术计算，不是机器人实测。DIP→指尖现在可由 v4 `*_tip` 点经 FK 计算；该距离仍是 CAD/URDF 几何量，不是真实硬件测量。全手指长还包括这个末段，不能只用已知两段之和替代。

## 5. 第三步：拟合 MANO 的固定几何

**先做尺度基线，再做形状拟合；这一阶段不需要训练网络。**

### 5.1 建立不会随姿态轻易变化的尺寸目标

从选定的点得到指节中心距、指根间距与掌部参考距离。选用来自已定义掌部点的掌宽；如果使用网格外轮廓掌宽，MANO 一侧也应取表面外轮廓，不能一边用关节中心、一边用外壳边缘。

参考姿态下的 MANO 几何描述记作 g_M(β)，L20 的目标描述记作 g_L20。对于采用表面指尖的末段，MANO 姿态校正可能改变其距离，因此在固定参考姿态计算，并另行记录动作下的变化。

计划的第一步：固定 β=0 与定义好的参考姿态，仅拟合正尺度 s，使总体大小接近。这是必须保留的几何基线。

计划的第二步：优化 s 与 β，比较新增形状参数是否改善比例误差：

```text
min_{β, s>0}  Σ_r w_r · ((s·g_M,r(β) − g_L20,r) / d_ref)^2
              + λ_β · ||β||²
```

d_ref 是事先定义的掌部尺度，用于无量纲化；w_r 是各部位权重；λ_β 防止形状参数过度偏离人手统计范围。β 不是“第 1 个参数=食指长度”的控制杆，通常需优化求解。权重、范围与停止条件都是计划，需用开发/验证样本确定后冻结，不能用正式测试样本调参。

### 5.2 再对齐参考姿态的点布局

通过掌部点先求旋转 A 与平移 b。然后用关键点位置细化，候选目标是：

```text
L = L_尺寸 + λ_p Σ_k w_k ||s·A·x_M,k(β, θ_ref) + b − x_L20,k(q_ref)||² / d_ref²
    + λ_β||β||² + λ_θ||θ_ref − θ_neutral||²
```

形状阶段优先固定 θ_ref；如果机器人拇指基部布局与中性人手差异较大，再允许少量已指定的基部旋转调整，并保存其偏离值。**不要第一次就让 45 个姿态参数与 β 完全自由地联合拟合一个张手姿态**，否则可以靠弯曲/扭转把点凑近，掩盖比例不匹配；单个姿态也不能确定唯一的真实 β。

可用 Adam 做初步优化，或用适当的非线性最小二乘法。保存多次初始化、收敛状态与最终残差；当前不指定未经验证的迭代数、学习率或精度。

输出至少包括 `beta_R`、`scale`、`alignment`、`theta_ref`、点提取规则、模型版本、目标单位以及逐部位误差。没有 MANO 模型与指尖定义时，这一步仍是未运行。

## 6. 第四步：检查拟合是否适合后续映射

计划验证按 [统一测评规则](../experiment/evaluation.md)进行：

1. 固定参考姿态画机器人点与 MANO 点叠图，分别看掌部、拇指和四指，而不只看整体外观。
2. 比较“仅尺度”与“尺度+β”的逐指长度相对误差、关键点绝对误差（mm）和最大部位误差；结果均待运行。
3. 冻结 β_R、s 与对齐，再在事先选定的张手、弯指、握拳、拇食指/拇中指捏合、展开等调试动作上检查。动作姿态通过明确的旋转转换或优化获得，不逐项复制 URDF 标量角到 MANO 轴角数组。
4. 报告动态动作的任务残差、求解失败及不可达样本。机器人与 MANO 可达空间不同，动态点不完全重合不必然说明静态 β 拟合错误。
5. 按后续任务要求在运行前确定可接受阈值；不把单个漂亮姿态、均值下降或固定 1 mm 阈值当作已经验收。

纯 MANO 拟合如果残差过大，可以比较：原始 MANO β+尺度；MANO 关节语义下的可调骨长骨架；直接几何关键点中间表示。后两者是扩展/替代表示，不能继续声称是未经修改的标准 MANO 参数模型。修改骨架后，原有 MANO 蒙皮与姿态校正也需要重新验证。

## 7. 怎样接回两阶段网络

```text
准备目标几何：L20 URDF + 指尖定义 → 拟合并冻结 β_R、s、对齐
准备机构描述：URDF mimic + 匹配版本的 SDK/标定 → E_L20

源人手动作 + 源几何 + 固定目标几何
                  ↓ 第一阶段：跨人手尺寸网络
              θ_R(t) 或 X_R(t)
                  ↓ 第二阶段：机构与驱动约束映射
              u_L20(t)
                  ↓ 已核查的命令/机构关系 ψ
              q_L20(t) → FK → 任务表现
```

当前文件可先构造从 16 个独立运动学角度到 21 个 q 的线性 mimic 展开。但独立运动学角度仍不是硬件执行器命令 u；只有补齐 SDK 槽位、单位、零点与方向后，才能构成实际 `q=ψ(u;E)`。

基线仍按项目顺序推进：先模型/FK 核查，随后简单归一化、角度迁移和已有优化重定向。固定 R 的几何可以先准备，不必先训练 URDF→MANO 网络；两个核心网络的新增收益另行实验检验。
