L20 左手：从 URDF 建立 MANO 虚拟人手 R

日期：2026-10-14（Asia/Shanghai）。状态：来源核查与建模计划；MANO 拟合、FK 可视化、基线与训练均未运行。

用户已提供 L20 左手 URDF 的官方仓库入口及本地 URDF/网格、MANO_LEFT.pkl。独立环境与 MANO 加载检查已完成，见 环境使用说明；硬件批次、L20 FK 与几何拟合仍待验证。本指南延续 两阶段研究主线：先跨人手尺寸，再处理目标机器人的驱动与耦合。URDF→R 是目标几何准备模块。

1. 可以建立什么

可以尝试用 L20 的几何信息，拟合一个尺寸、指节比例和指根布局尽量接近它的 MANO 虚拟人手 R。拟合结果需要有逐部位残差；能否满足后续映射要求，必须实际运行后判断。

URDF 与 MANO 是两套不同的模型，不能直接按字段转换：URDF 描述机器人刚性部件与运动连接；MANO 的形状空间来自人手扫描，具有固定的人手拓扑与统计相关性。MANO 的 β 不能逐项任意指定每根指骨、关节轴或驱动耦合。

把 R 分为两个部分：

  • 固定几何：拟合得到的 β_R、全局尺度 s、选定的关键点规则和与机器人掌部坐标系的对齐。每个目标机器人/模型版本固定一套。
  • 变化动作：每一帧的 θ_R(t)，由第一阶段产生。不要每帧重新拟合 β_R，否则机器人几何会随动作漂移。

一个候选表达是 X_R(t) = s · A · K(MANO_left(β_R, θ_R(t))) + b。K 提取事先定义的对应点；A 是三维旋转矩阵；b 是坐标平移；s 是额外的正尺度。尺度、旋转、平移不属于 MANO 形状参数 β。

R 的动作空间保留虚拟人手的能力。机器人限位、真实驱动与 mimic 留给第二阶段，不在 R 里预先强行施加 L20 的五条联动约束。

项目 文件中的内容 含义

四指的简化链：hand_base_link → *_metacarpals → *_proximal → *_middle → *_distal。对应关节依次是 *_mcp_roll → *_mcp_pitch → *_pip → *_dip，其中 * 是 index、middle、ring、pinky。

文件写明：

q_index_dip  = 0.8917 · q_index_pip
q_middle_dip = 0.8917 · q_middle_pip
q_ring_dip   = 0.8917 · q_ring_pip
q_pinky_dip  = 0.8917 · q_pinky_pip
q_thumb_ip   = 1.1619 · q_thumb_mcp

全部 offset 为 0。这是该 URDF 的固定线性近似，并非对真实连杆在全部工况下准确性的验证。所选 FK/仿真库是否自动处理 mimic，也需要显式检查。

厂商 L20 页面标注 16 个主动自由度与 5 个被动自由度；厂商 ROS SDK的 L20 数组有 20 个槽位，其中 4 个为 Reserved。两者与本文件的数量结构相容，但 SDK 槽位顺序、单位、零点、方向、硬件版本与 URDF 的具体对应仍待核查。L20 与 L20 Lite 也不能混用。

4. 第二步：从机器人提取有语义的几何点

4.1 先固定单位、坐标和参考姿态

计算采用米与弧度；报告距离时再转换为毫米。核对 STL 尺度是否与 URDF 一致，不能因为 STL 文件没有单位字段就默认其尺寸正确。

先用所有独立关节角为零作为文件参考姿态，按 mimic 补全从动关节。零姿态是否适合作为张手，需要看模型；尤其拇指有非零固定 rpy，不可把全部 rpy 清零。若选其他参考姿态，保存确切 q_ref。

URDF 的关节位置相对父 link。对每个关节沿整条链计算：

T_child(q) = T_parent(q) · T_origin(xyz, rpy) · T_axis_rotation(q_joint)

关节轴是在关节局部系定义的。不要直接把各关节 <origin xyz> 堆成全局点，也不要用 <inertial origin> 的质心作为关节中心。

定义虚拟腕部位置，并保存其相对 hand_base_link 的变换。掌面方向可由已选指根点建立；使用一致的右手坐标系，轴方向写清。MANO 与机器人必须是同一侧，避免通过镜像反射掩盖错误。

4.2 计划的 21 点对应

下表是候选语义对应，必须在叠图后确认。机器人机械关节中心与人体关节中心只作近似对应。

点组 机器人取点规则 MANO 一侧
腕部 1 点 选定的腕/掌基准点，保存局部坐标 腕部骨架点
四指各 4 点 *_mcp_pitch、*_pip、*_dip 的 FK 关节原点，再加 *_distal 内定义的指尖点 掌指关节 MCP、近端指间关节 PIP、远端指间关节 DIP、指尖
拇指 4 点 暂以 thumb_cmc_pitch 原点作为基部候选，接 thumb_mcp、thumb_ip 原点与 distal 内指尖 基部 CMC、MCP、IP、指尖

四指 mcp_roll 与 mcp_pitch 原点相距约 16.77 mm，所以不能把这两个机械轴都强塞进一个人体 MCP 点。拇指基部多轴且有偏移，选 cmc_pitch 是候选几何代理；若拟合或动作误差集中于这里，需要重新评估代理或改用更多辅助点。

在每个末节 STL 上标注一个约定明确的末端点，例如指腹末端中心。保存 tip_local_xyz，并把网格坐标经 visual 的 origin/scale 转成 link 坐标，再由 FK 转成掌部坐标。不要把 distal link 原点当指尖，也不要把网格包围盒的某个最大坐标未经检查直接当指尖。

提取结果计划保存为 landmarks_reference.json：点名、所属 link/关节、局部点、参考姿态下的全局位置、单位、左右手、坐标系、对应规则和来源版本。指尖尚未选定时标记缺失，不填猜测坐标。

4.3 一个已能从关节原点得到的长度例子

食指 MCP_pitch→PIP 的中心距为：

sqrt((-0.0041945524)^2 + 0^2 + (0.0448194356)^2)
≈ 0.0450153 m = 45.02 mm

PIP→DIP 中心距约 31.82 mm。这是对当前文件坐标的算术计算，不是机器人实测。DIP→指尖仍缺 tip_local_xyz，不能通过质心位置推断。全手指长还包括这个末段，不能只用已知两段之和替代。

5. 第三步：拟合 MANO 的固定几何

先做尺度基线，再做形状拟合；这一阶段不需要训练网络。

5.1 建立不会随姿态轻易变化的尺寸目标

从选定的点得到指节中心距、指根间距与掌部参考距离。选用来自已定义掌部点的掌宽；如果使用网格外轮廓掌宽，MANO 一侧也应取表面外轮廓，不能一边用关节中心、一边用外壳边缘。

参考姿态下的 MANO 几何描述记作 g_M(β)，L20 的目标描述记作 g_L20。对于采用表面指尖的末段，MANO 姿态校正可能改变其距离，因此在固定参考姿态计算，并另行记录动作下的变化。

计划的第一步：固定 β=0 与定义好的参考姿态，仅拟合正尺度 s，使总体大小接近。这是必须保留的几何基线。

计划的第二步：优化 s 与 β，比较新增形状参数是否改善比例误差：

min_{β, s>0}  Σ_r w_r · ((s·g_M,r(β) − g_L20,r) / d_ref)^2
              + λ_β · ||β||²

d_ref 是事先定义的掌部尺度，用于无量纲化；w_r 是各部位权重；λ_β 防止形状参数过度偏离人手统计范围。β 不是“第 1 个参数=食指长度”的控制杆，通常需优化求解。权重、范围与停止条件都是计划，需用开发/验证样本确定后冻结，不能用正式测试样本调参。

5.2 再对齐参考姿态的点布局

通过掌部点先求旋转 A 与平移 b。然后用关键点位置细化，候选目标是：

L = L_尺寸 + λ_p Σ_k w_k ||s·A·x_M,k(β, θ_ref) + b − x_L20,k(q_ref)||² / d_ref²
    + λ_β||β||² + λ_θ||θ_ref − θ_neutral||²

形状阶段优先固定 θ_ref；如果机器人拇指基部布局与中性人手差异较大，再允许少量已指定的基部旋转调整，并保存其偏离值。不要第一次就让 45 个姿态参数与 β 完全自由地联合拟合一个张手姿态，否则可以靠弯曲/扭转把点凑近，掩盖比例不匹配；单个姿态也不能确定唯一的真实 β。

可用 Adam 做初步优化，或用适当的非线性最小二乘法。保存多次初始化、收敛状态与最终残差；当前不指定未经验证的迭代数、学习率或精度。

输出至少包括 beta_R、scale、alignment、theta_ref、点提取规则、模型版本、目标单位以及逐部位误差。没有 MANO 模型与指尖定义时，这一步仍是未运行。

6. 第四步：检查拟合是否适合后续映射

计划验证按 统一测评规则进行：

  1. 固定参考姿态画机器人点与 MANO 点叠图，分别看掌部、拇指和四指，而不只看整体外观。
  2. 比较“仅尺度”与“尺度+β”的逐指长度相对误差、关键点绝对误差（mm）和最大部位误差；结果均待运行。
  3. 冻结 β_R、s 与对齐，再在事先选定的张手、弯指、握拳、拇食指/拇中指捏合、展开等调试动作上检查。动作姿态通过明确的旋转转换或优化获得，不逐项复制 URDF 标量角到 MANO 轴角数组。
  4. 报告动态动作的任务残差、求解失败及不可达样本。机器人与 MANO 可达空间不同，动态点不完全重合不必然说明静态 β 拟合错误。
  5. 按后续任务要求在运行前确定可接受阈值；不把单个漂亮姿态、均值下降或固定 1 mm 阈值当作已经验收。

纯 MANO 拟合如果残差过大，可以比较：原始 MANO β+尺度；MANO 关节语义下的可调骨长骨架；直接几何关键点中间表示。后两者是扩展/替代表示，不能继续声称是未经修改的标准 MANO 参数模型。修改骨架后，原有 MANO 蒙皮与姿态校正也需要重新验证。

7. 怎样接回两阶段网络

准备目标几何：L20 URDF + 指尖定义 → 拟合并冻结 β_R、s、对齐
准备机构描述：URDF mimic + 匹配版本的 SDK/标定 → E_L20

源人手动作 + 源几何 + 固定目标几何
                  ↓ 第一阶段：跨人手尺寸网络
              θ_R(t) 或 X_R(t)
                  ↓ 第二阶段：机构与驱动约束映射
              u_L20(t)
                  ↓ 已核查的命令/机构关系 ψ
              q_L20(t) → FK → 任务表现

当前文件可先构造从 16 个独立运动学角度到 21 个 q 的线性 mimic 展开。但独立运动学角度仍不是硬件执行器命令 u；只有补齐 SDK 槽位、单位、零点与方向后，才能构成实际 q=ψ(u;E)。

基线仍按项目顺序推进：先模型/FK 核查，随后简单归一化、角度迁移和已有优化重定向。固定 R 的几何可以先准备，不必先训练 URDF→MANO 网络；两个核心网络的新增收益另行实验检验。
