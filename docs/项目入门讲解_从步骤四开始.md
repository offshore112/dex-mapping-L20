# 项目入门讲解：从步骤四开始

日期：2026-10-24。用途：先理解项目在做什么，再逐步阅读公式。

**本讲解覆盖步骤四到步骤十三，以及后面的测试。先把整条流程串起来理解，不要求只停留在步骤四；再按需要回看某一步。**

原技术文档把流程、矩阵、优化和测试同时展开，阅读门槛偏高。这份讲解按相同流程解释，但不要求你先学会矩阵运算、旋转公式或神经网络。

**本轮只是整理讲解，没有继续实验、采集、训练或开发。**

## 先用一分钟分清四个对象

| 对象 | 是什么 | 当前能相信到哪里 |
|---|---|---|
| 你的真实手 | 摄像头前真正做动作的手 | 它是我们想重现的对象；现有录制没保存同步真实视频 |
| 个人拟合手 | 根据检测点，用 MANO 计算出的个人手模型 | 是估计结果，可能有错误 |
| 固定虚拟手 R | 提前准备好、形状固定的目标人手模型 | 当前是候选；动作自然性尚未通过验收 |
| L20 | 机器人手的机械模型，之后才可能连接实物 | 文件运动学有检查，当前没有可靠真机闭环 |

MANO 是一套现成的可调人手模型。个人拟合手和 R 都可以用它生成，但用途不同：

- 个人拟合手尽量描述“你的手长什么样、现在怎么动”。
- R 是“所有操作者准备去控制的同一只目标虚拟手”。

你现在先记住两个符号：

- **β：手的形态。** 包括模型能够表达的掌形、指长比例等；不是每一维单独控制一根手指。
- **θ：手的姿态。** 描述当前各关节怎样旋转。

整体缩放另有“尺度”参数。把手整体放大和改变指节比例，是两件不同的事。

## 先看整条路线

~~~text
准备一只固定 R
        ↓
摄像头看到你做动作
        ↓
找出图像中的手部点
        ↓
计算你的个人手模型及动作
        ↓
把动作放到固定 R 上
        ↓
将目标动作转成 L20 关节角
        ↓
核实执行器接口后，才可能控制真实 L20
~~~

这条路线展示的是目标流程，不能把每个箭头都理解成已经验收完成。

目前，你的完整个人录制已经到“固定 R 的离线回放”；动作质量还没通过。L20 关节求解在另一些合成样本和旧真实小样本上有记录，尚未接到当前这段完整固定 R 序列。

## 用一次“拇食指捏合”把后续步骤连起来

以下用你在摄像头前做一次捏合为例。前半段描述当前本人数据的处理，后半段机器人求解属于已有的另一条测试支路，不能理解成当前完整个人序列已经全部走通。

| 原文步骤 | 这一步解决的问题 | 产生的东西交给谁 |
|---|---|---|
| 四：固定 R | 先准备好以后大家控制的那只目标手 | 保存 R 的固定几何，供动作迁移使用 |
| 五：摄像头采集 | 你做捏合时，腕、指节、指尖在哪里？ | 得到位置点，交给坐标整理 |
| 六：坐标规范化 | 换到以腕和手掌为参考的观察方式 | 整理后的点交给个人模型拟合 |
| 七：个人 MANO 拟合 | 哪种手形和关节姿态能接近这些点？ | 得到个人形态及逐帧姿态 |
| 八：小指处理 | 拟合里已发现的小指末节扭转能否减小？ | 候选修正姿态交给迁移步骤 |
| 九：个人动作→R | 让目标 R 按这些姿态动起来 | 当前复制姿态，得到 R 的动作 |
| 十：功能特征 | 怎样判断方向、弯曲和捏合关系接近多少？ | 特征既用于比较，也给后续求解作目标 |
| 十一：条件化目标 | 当前 R 和 L20 比例不同，怎样准备机器人目标？ | 另建 L20 比例目标骨架，保留原 R 的任务关系 |
| 十二：q 求解 | L20 在轴、限位、联动允许下怎样接近目标？ | 得到关节角，交给机器人显示；实际驱动接口另核实 |
| 十三：显示回放 | 已计算的形状和动作到底呈现什么样？ | 显示、动画和供人检查的画面 |

再把它们归到三个大环节：

- **前处理：**摄像头点→个人形态与动作。先弄清“你大致怎么动”。
- **研究第一阶段：**个人动作→固定 R。当前只用复制姿态作为基线，跨操作者网络未训练。
- **研究第二阶段：**R 动作→受约束的 L20 动作。已有部分样本的关节优化，实际执行器和真机未验证。

固定 R 的构造是预先准备；特征是多个环节共用的比较工具；显示是观察工具。它们不意味着项目另有多个研究映射阶段。

## 步骤四：先准备一只固定的目标虚拟手 R

**这一关只回答：以后大家要控制的虚拟手，长什么样、放在哪里？**

你可以想象桌上有一个已经做好的手模型。现在允许你：

1. 把它整体放大或缩小。
2. 将它整体转动。
3. 把它搬到合适的位置。

当前 R 的准备基本就是这件事：采用标准 MANO 手形，再利用 L20 的参考点，确定 R 的整体大小、朝向和位置。

| 问题 | 回答 |
|---|---|
| 输入是什么？ | 标准 MANO 手形、L20 的参考点 |
| 做什么？ | 整体缩放、转动、平移，让二者在参考位置上尽量接近 |
| 输出是什么？ | 一只形状与放置固定的 R |
| 这时有个人动作吗？ | 没有，这一步先准备目标手 |

原文的“7 个自由度”只是在数：整体缩放 1 个，旋转 3 个，平移 3 个。先理解这三种操作即可，暂时不用推导求解公式。

**关键限制：**整体放大一只人手，不能单独把掌变窄、把小指变长。因此当前 R 只在整体长度上接近 L20，掌宽和指长比例仍不一致。它不能称为 L20 的精确几何替身。

当前 β_R=0 的意思是“采用标准 MANO 手形”，不是 R 没有形状。R 的动作 θ_R 以后可以改变，固定形态不等于固定动作。

读完这一关，你只需要能够说出：**先固定目标手，再把不同人的动作映射到它上面。**

## 步骤五：摄像头把你的手变成一组位置点

**这一关只回答：画面中的腕部、指节附近和指尖在哪里？**

例子：你在摄像头前做一次拇食指捏合。检测器找出腕、各指节和指尖等位置，输出一组 21 个点。

| 输入 | 做什么 | 输出 |
|---|---|---|
| 摄像头图像 | 用 MediaPipe 检测手部位置 | 21 点、左右手标签、时间戳等 |

这时得到的是“点在哪里”，还没有直接得到你的 β、θ，也没有得到机器人关节角。

检测点可能受遮挡、视角等影响。检测到手，不代表每个点都准确。

原文中的世界点原点、镜像、置信阈值属于此步骤的技术细节。第一次读时先不推导，但不能因此认为这些问题已经全部验证。

## 步骤六：给这组点采用统一的观察方式

**这一关只回答：如何避免把整只手的搬动和转向，误当成手指动作变化？**

想象你保持捏合姿态，把整只手向左移动。我们希望描述的手指动作仍是捏合，而不是因为画面位置改变就变成另一个动作。

因此计算时：

1. 先把腕部当作局部参考位置。
2. 再按手掌方向建立局部坐标。
3. 用这套坐标重新描述各点。

| 输入 | 做什么 | 输出 |
|---|---|---|
| 检测器的三维点 | 减去腕部位置，按手掌方向换坐标 | 统一观察方式下的米制点 |

这里准备给个人 MANO 拟合的点仍保留米制大小，没有把不同指长比例消除掉。

原文的坐标轴、投影、矩阵转置，是实现“换观察方式”的计算工具。你先理解目的，之后再学习这些工具。

## 步骤七：用这些点，计算你的个人手模型

**这一关只回答：哪一种手形和动作，能够产生接近检测点的位置？**

可以把它想成在电脑里调整一只可调人手：

- 改形状，让掌宽和各指比例更接近观测。
- 改整体大小，让尺度更接近观测。
- 改各关节旋转，让模型点接近检测点。

电脑反复调整参数、计算点的位置、比较差异。这叫“拟合”。

| 输入 | 做什么 | 输出 |
|---|---|---|
| 规范化后的 21 点序列、MANO 模型 | 调整模型参数以接近观测 | 个人 β_i、尺度及每帧 θ_i 等 |

为了避免同一个人的手一帧变大、一帧变小，现有方法分两步：

1. 用一组校准帧估计个人形态和尺度。
2. 固定这些形态参数，再拟合逐帧动作。

这里的两步是“估计个人手”的内部步骤，和研究中的“人体尺寸映射→机器人驱动映射”不是同一件事。

原文的“损失函数”可以先理解成**给候选结果打分的规则**：

| 打分项 | 在检查什么 |
|---|---|
| 点位置项 | 模型点离检测点远不远 |
| 骨段长度项 | 相邻点之间的长度差大不大 |
| 姿态先验 | 参数是否过于极端；当前还不足以保证解剖合理 |
| 平滑项 | 相邻帧有没有突然变化 |

电脑想找到总分更低的参数。**“接近检测点”不等于“接近真实手的一切细节”**：现有拟合仍有异常扭转，当前也缺同步真实视频验证。

## 步骤八：处理小指末节已经发现的一种异常

**这一关只回答：能不能在尽量不改变原点位置的情况下，减少小指末节的异常扭转？**

你可以想象一根笔：笔尖位置不动，把笔绕自身长轴转动，笔身上的标记方向仍会变化。

手指也有类似问题：指尖位置可以接近观测，但指甲方向仍可能不自然。因此只检查点的位置，未必能发现全部旋转问题。

当前处理只重新求小指末节的旋转，倾向于选择扭转较小、同时保留原拟合点的解。

| 输入 | 做什么 | 输出 |
|---|---|---|
| 原个人拟合姿态与点 | 只调整小指末节旋转，并检查点没有明显改变 | 一份小指处理后的候选姿态 |

它没有重建手形，也没有修复所有手指；更没有真实指甲朝向作为答案。原文的四元数、雅可比、Gauss–Newton，第一次读可以跳过。

## 步骤九：让固定 R 按你的拟合姿态动起来

**这一关只回答：已有个人姿态，怎样先驱动同一只固定 R？**

当前做法是直接复制 θ：

~~~text
个人拟合手：使用个人形态 β_i，动作是 θ_i
固定目标 R：保持目标形态 β_R，动作暂时也用 θ_i
~~~

你已经理解的 θ_R=θ_i 就在这里。

| 输入 | 做什么 | 输出 |
|---|---|---|
| 个人拟合姿态、固定 R | 将局部旋转参数应用到 R | R 的逐帧形状和点 |

这一步中，R 不会变成与你一样大小；也不跟随你整只手在空间里的移动和整体转向。当前主要显示手内部姿态变化。

由于指长、掌宽不同，相同旋转可能产生不同指尖间距。因此它是一个简单的直接迁移对照，不是完整的跨尺寸方法。

**当前已有：**你一段录制到固定 R 的离线回放。

**当前未完成：**多操作者跨尺寸验证、任务保持补偿的完整比较、第一阶段网络训练。整体动作自然性仍未通过验收。

## 步骤十：把复杂动作变成几个能比较的量

**这一关只回答：怎样用数字描述“两只手的动作接近多少”？**

不用一开始比较整张皮肤，可以先检查：

| 比较对象 | 可以怎样理解 |
|---|---|
| 骨段方向 | 手指各段的箭头朝向是否接近 |
| 相邻骨段夹角 | 各处弯了多少 |
| 指尖间距 | 拇食指等指尖对是靠近还是分开 |
| 相对长度 | 一段长度占掌部参考长度的多少 |

这些叫功能特征：人为选定、可以直接计算的动作描述。

| 输入 | 做什么 | 输出 |
|---|---|---|
| 手的 21 点 | 计算方向、夹角、距离等 | 一组用于比较和求解的特征 |

这里出现的归一化，是为了让整体大小不同的手有一致的比较口径；它不自动消除指长比例差异，也不自动成为学习得到的共享表示 z。

第一次读时，你只需要知道“我们用这些量检查动作”，不必记住每组量有多少维。

## 步骤十一：给机器人求解准备一套 L20 比例的目标骨架

**这一关只回答：R 是自然人手比例，机器人是机械手比例，目标该怎样表达？**

当前有两种不同用途的表示：

| 表示 | 用途 |
|---|---|
| 自然 MANO 人手表面 | 让人看清虚拟手动作 |
| L20 比例的目标点/骨架 | 给机器人关节求解提供形状目标 |

做法是用 L20 的参考骨段长度，再参考源动作的方向变化，构造一套供求解器追踪的目标点。

| 输入 | 做什么 | 输出 |
|---|---|---|
| 源动作、L20 参考几何 | 用 L20 的长度构造携带动作变化的目标 | L20 条件化目标骨架 |

这里没有把 MANO 皮肤直接改造成 L20 外壳；构造目标点也不保证机器人全部能到达，下一步仍要受关节约束求解。

这条支路有合成样本和旧真实小样本记录，尚未接到当前这段完整个人 R 序列。

## 步骤十二：计算 L20 应该采用哪些关节角

**这一关只回答：在机器人允许的运动范围内，哪些角度能尽量接近目标？**

电脑会反复：

1. 选择一组允许范围内的角度。
2. 按文件联动规则补齐从动关节。
3. 计算机器人指尖会到哪里。
4. 与目标比较，再调整角度。

| 输入 | 做什么 | 输出 |
|---|---|---|
| 目标特征、L20 运动学与限位 | 有约束地寻找合适角度 | L20 独立关节角 q 及从动角 |

有些目标不能同时满足，求解器只能按设定的优先级折中；它不会自己知道你真正想做什么。

原文的 mimic 就是文件中的联动规则。例如，某些关节不能分别选角度，要随主关节按规定关系运动。它属于研究第二阶段要处理的问题。

还要区分：

- q：机器人关节处于什么角度。
- u：给实际执行器发什么命令。

当前有 q 级优化基线，实际 u、SDK 和真机仍未验证。不能把一串关节角直接当作已验证的电机命令。

原文的残差、权重、多起点、整段优化，第一次读只需知道它们分别用于“比较误差、安排优先级、多试初值、一起考虑连续动作”。

## 步骤十三：把已有结果显示成动画

**这一关只回答：计算出的模型和动作，能否按数据播放出来？**

| 输入 | 做什么 | 输出 |
|---|---|---|
| 表面顶点或关节角序列 | 用 MuJoCo 显示、按时间更新 | 窗口、图片、GIF |

当前 R 动画是按已有数据改变表面形状，不是在做真实抓取的物理仿真。

并排画面里的金色手是个人拟合模型，蓝色手是 R。金色手不是摄像头真实视频，因此二者相似不能证明都忠于真实动作。

当前完整输入有 774 帧，GIF 是覆盖整段的采样预览，预览图数量少一些不表示原数据被丢掉。

## 看到“测试通过”，先问它通过了什么

| 测试层级 | 在问什么 | 当前状态 |
|---|---|---|
| 程序、接口、显示 | 文件读对了吗？坐标一致吗？动画按数据显示了吗？ | 有通过记录 |
| 本人动作质量 | 是否像你的真实动作？是否自然？ | 尚未通过用户验收 |
| 当前完整序列的 L20 q | 机器人是否实现对应目标？ | 尚未接入当前完整固定 R 序列 |
| 实际执行器与真机 | 命令能否正确、安全地执行？ | 未验证 |
| 多操作者与网络 | 新操作者能否映射好？网络是否优于基线？ | 未开展正式验证，网络未训练 |

原文数字也要按“比较对象”读：

- 对检测点的拟合误差：模型离检测器输出有多远。
- 源/R 动作特征误差：R 与个人拟合模型的关系有多接近。
- R/L20 静态几何误差：两个候选几何在参考状态下有多不同。

这三类数字不能混成一个“整个项目的准确率”。

## 现在可以先跳过哪些内容

第一遍先跳过：SVD、旋转矩阵推导、四元数、雅可比、求解器容差、各项权重数字和潜变量 z 的训练细节。

以后按需要回来：

| 想弄懂的问题 | 再查原文什么内容 |
|---|---|
| 手形怎样改变 | β、形状基 |
| 手指怎样旋转 | θ、旋转、父子骨架 |
| 怎样把点换到同一个参考系 | 坐标变换 |
| 电脑怎样找到参数 | 损失函数、优化 |
| 怎样比较动作好坏 | 功能特征、指标定义 |
| 怎样用网络代替或改进映射 | 监督目标、网络、z 候选 |

当前不要把“必须先学完所有公式”当成阅读前提。先把步骤四及以后的整条链理解清楚，再按需要展开某一步的**输入、操作、输出、当前状态**和计算。
