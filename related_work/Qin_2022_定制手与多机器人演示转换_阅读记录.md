## 一句话问题与方法

论文先从单摄像头 RGB-D 流估计操作者的手腕位姿、SMPL-X 姿态和形状参数；再根据初始化时的操作者手部几何，在 SAPIEN 中即时构建一个与该操作者骨架结构和尺寸相似的定制手。采集时直接把 SMPL-X 手部姿态作为定制手的控制目标，从而绕过在线的人手到指定机器人手的迭代重定向。采集完成后，再把定制手轨迹离线转换到 Schunk、Adroit、Allegro 等指定机器人手。

## 定制手是怎样构建的

1. 用 MediaPipe 做检测框，用 FrankMocap 回归 SMPL-X 手部的姿态和形状；在初始化的较好视角中保存形状参数，后续把它当作固定的手部几何参考。论文第 IV-B、IV-C 节明确区分了每帧姿态和初始化形状。
2. 将手腕放在规范坐标系原点，读取重建人手的关节骨架和指尖位置。仓库 `example/customized_robot_hand.py` 的 `forward_smplx` 先把关节位置减去腕部基准，再按统一的 21 点顺序使用这些位置。
3. 在仿真器中不直接用完整 SMPL-X 网格作为可动刚体，而是用盒体表示掌部、用胶囊体表示各指节，依据骨架点之间的距离和方向设置 link 的长度与相对姿态。仓库 `hand_teleop/kinematics/mano_robot_hand.py` 的 `create_mano_full_dof_robot_hand` 实现了这一过程。
4. 定制手使用 15 个三轴球关节，共 45 个姿态自由度，与 SMPL-X 手部姿态参数对应。因此采集时可以近似直接把视觉姿态作为定制手的关节目标；这一步成立的前提是“定制手的运动学结构就是操作者的人手结构”，并不意味着它已经是某个真实机器人的机构模型。
5. 论文还用低通滤波和 PD 控制稳定视觉驱动；形状参数相对初始化值的偏离被用作置信度，置信度低时降低控制刚度。这个机制是视觉遥操作稳定化措施，不是虚拟手几何拟合方法本身。

## 与本项目的对应关系

| Qin 等人的定制手 | 本项目的机器人几何对应虚拟手 `R_j` |
|---|---|
| 每个操作者一套，形状和骨架跟随操作者 | 每个目标机器人模型一套，几何和指根布局跟随目标机器人 |
| 目标是采集时提供直观的人手界面 | 目标是把人手尺寸差异先转换成目标几何下的中间动作 |
| 45 个三轴姿态自由度，采集时不施加指定机器人约束 | 保留用于第一阶段的虚拟动作空间；L20 限位、`mimic` 和执行器约束放到第二阶段 |
| 采集后再对指定机器人做离线重定向 | 可把这套离线 FK 优化作为 `R_j → q_j` 的起始基线和教师标签生成器 |
| 盒体/胶囊体主要为实时仿真和碰撞稳定服务 | `R_j` 的几何拟合应先使用 L20 URDF、网格和已定义参考点；碰撞代理可以单独简化，不能替代真实机构描述 |

因此，**可以参考它的“从几何参数生成可动手模型”的方法，但不能直接把它的 45-DoF 定制手当作我们的 L20 虚拟手**。它的虚拟手按操作者变化；本项目固定 L20 时，所有操作者共享同一个由 URDF 定义的 `R_L20`，换机器人时才生成相应的 `R_j`。

## 可以直接借用的设计

- **初始化后冻结形状**：像论文固定初始化形状一样，`R_j` 应固定 `beta_R`、尺度、刚体对齐和 `theta_ref`，不要在每一帧重新拟合形状。当前 L20 的 v5 结果已经保存了这一套固定参数。
- **骨架驱动的程序化构建**：从目标 URDF 的 FK 关节原点、网格指尖点和掌部参考点构造目标骨架；每个 link 的相对长度、方向和父子关系都由模型生成，而不是手工画一只“看起来像 L20”的手。
- **分离视觉表示和可执行机构**：可先让 `R_j` 以 MANO 网格或关键点骨架作为视觉/中间表示，再由第二阶段把它变成 L20 的 `q`。这与论文“采集定制手、离线转换指定手”的分层思想一致。
- **使用 FK 关键点损失和时间连续性**：论文的离线重定向目标是关键点 FK 误差加相邻时刻关节变化惩罚，并使用关节限位约束。这个目标适合先作为本项目的优化基线。
- **先做离线再接实时**：论文把计算量较大的重定向移到采集之后；本项目也应先在离线 MANO 序列上验证 `R_j → L20`，然后再接摄像头。

## 不应直接照搬的部分

- 不把每个操作者都建成一个新的 `R_j`；那会把人体尺寸差异吸收到虚拟手中，无法检验第一阶段是否真的完成了跨尺寸映射。
- 不把 SMPL-X/MANO 的 45 个轴角量逐项复制成 L20 的关节角。MANO 的局部轴角、L20 的关节轴和 `mimic` 关系不是同一组坐标。
- 不把论文中由逆动力学得到的模拟关节力矩直接当作 L20 的执行器指令。L20 当前只有 URDF 运动学与部分 `mimic` 信息，真实传动、单位、零位、方向和弹性行为还没有补齐；在这些信息缺失时只能输出模拟 `q`，不能声称得到真实 `u`。
- 不把论文的定制手实验数字当成我们的方法结果。论文的 17 名操作者、约 60 demos/h、各手型成功率等只说明其论文实验条件，不能转写为本项目性能。

## 对本项目的具体构建方案（计划）

### A. 目标几何准备模块：`URDF + mesh → R_j`

对每个目标机器人先生成一个固定几何描述：

```text
G_j = {骨架点、指尖点、掌部参考、尺度、坐标对齐、手指拓扑}
R_j = {beta_R, scale_R, alignment_R, theta_ref, K_R}
```

对 L20，继续使用当前 v4/v5 的约定：腕部、四指各 MCP/PIP/DIP/指尖、拇指 CMC/MCP/IP/指尖，共 21 个对应点；四指 DIP 与 PIP、拇指 IP 与 MCP 的 `mimic` 不写进 `R_j` 的固定几何，而写入后续机构描述。若 MANO 在拇指或机械 MCP 多轴处的残差持续偏大，候选替代是“MANO 外形 + 可调骨架”或“关键点图表示”，但需要用动态基线比较后再决定。

### B. 第一阶段：源人手尺寸 → `R_j` 动作

输入可以是源人手的 MANO 参数、关键点或两者；至少要显式带源人体形态信息。输出先选 `theta_R(t)` 或 `K_R(t)`，而不是直接输出 L20 电机量。候选损失包括：目标 `R_j` 关键点位置、指骨方向、捏合关系、姿态先验和时间平滑。目标几何 `G_j` 在这一阶段只作为目标条件；`beta_R` 不随时间变化。

### C. 第二阶段：`R_j` 动作 → L20 的 `q` / `u`

先实现可检查的优化基线：

```text
q_ind(t) = argmin 关键点 FK 误差
                   + 时间平滑
                   + 姿态偏好
             s.t. L20 限位
                  q_full = psi_urdf(q_ind; mimic)
```

当真实驱动描述 `E_L20` 补齐后再改为：

```text
u_L20(t) → q_L20(t) = psi(u_L20(t); E_L20) → FK → 任务特征
```

这里必须把 `q`（全部关节状态）和 `u`（独立执行器指令）分开记录。论文的 `q^R` 优化式可作为这个阶段的起点，但 L20 的 16 个独立运动学坐标、5 条 `mimic` 和真实驱动空间需要显式写入约束。

## 建议的最小对照实验（计划，均未运行）

在同一套离线 MANO 动作和同一 L20 目标上比较：

1. 源人手 → L20 的直接关键点/角度重定向；
2. Qin 风格的“按操作者生成定制手” → L20 离线优化；
3. 固定 L20 几何的 `R_j` → L20 离线优化；
4. 完整两阶段网络：源形态 → `R_j` 动作 → L20 机构/执行器输出。

第一、二项是判断目标几何中间表示是否有必要的参照；第三项是当前研究主线的最小闭环；第四项才用于检验学习方法是否超出优化基线。统一报告指尖/任务特征误差、捏合保持、限位违规、`mimic` 残差、平滑性、求解时延和配置成本。当前没有任何一项已运行。

## 当前判断与边界

Qin 等人的贡献对本项目最有用的地方不是“用 SMPL-X 生成一只虚拟手”这句话，而是把**源手的人体形态、交互界面、目标机器人的运动学转换**拆成可验证的模块。我们的转换是把“按操作者生成的定制手”改成“按机器人生成的 `R_j`”，再保留一个单独的机构/驱动阶段。这个方向与当前两阶段主线一致，但是否能减少跨操作者和跨机构调参，仍必须通过固定测试名单和直接映射消融验证。

尚未做的事情：没有在本项目环境复现作者仓库；没有把论文的 SAPIEN 代码直接移植到 L20；没有运行 `R_j → L20` 动态优化；没有验证真实 L20 驱动命令。
