# v15 功能特征基线：失败边界与诊断

## 1. v14 全绝对点目标保留为失败对照

v14 把 MANO-R 的 21 个绝对点直接当成 L20 21 个机械代理点目标。拇食指目标距离为 0.46 mm，但全点优化后的实际距离为 63.88 mm；拇中指目标/实际为 0.80/55.84 mm。这些结果保留在 `experiment/v14_R_L20_constraint_baseline/`，说明绝对点接口不适合作为当前 R→L20 目标。

## 2. v15 首次平衡权重运行

初始 v15 运行对所有方向、骨长、掌部展开和指尖对使用接近的权重。拇食指和拇中指的归一化距离仍分别约为 0.155 和 0.177，任务关系没有被优先满足。该现象定位为目标函数权重冲突：全手特征正则项阻止了可达的任务指尖关系。

## 3. v15 当前任务优先运行

对带有 `tip_pair` 的动作降低非相关全手项，提高选定指尖距离权重到 30.0，并把其它特征保留为正则项。重跑后拇食指和拇中指的归一化距离误差为 0.0003 和 0.0004，说明功能特征接口可以把任务关系传给 L20 q。

## 4. 尚未解决的边界

- 选定指尖距离小不等于真实接触；未计算接触法向、接触面积、穿透或物体任务成功率。
- 结果是三个固定合成 MANO 动作，不是摄像头数据、训练集或泛化结果。
- 当前只有 q 级 URDF 约束；真实执行器 `u`、驱动零位、方向、肌腱和弹性仍缺失。
- 当前还没有时间序列平滑项，也没有将优化结果作为在线控制器验证。
- MuJoCo 场景使用 ASCII 路径；中文父目录会触发 Windows MuJoCo 资源读取失败。

## 5. MuJoCo 碰撞探索的边界

对当前 URDF 导出的碰撞几何做了只读接触计数探索。零姿态和三组 q 解都出现多个负距离接触，且部分来自相邻/非相邻 link 的重叠网格；这说明现有 URDF 碰撞几何不能直接作为 v15 的接触损失。接触结果没有写入正式指标，也没有被解释为动作失败。后续需要先建立经过相邻 link 过滤、碰撞网格清理和接触点语义标注的 L20 碰撞描述，再把碰撞项加入优化。
