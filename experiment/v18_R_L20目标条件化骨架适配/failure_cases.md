# v18 目标条件化骨架适配边界

## 1. 不能只迁移 L20 形状而忽略任务

第一次 v18 尝试只把 MANO 相对方向迁移到 L20 零位骨长和方向，拇食指原始捏合目标的归一化距离从 `0.0167` 被改变到约 `0.82`，说明形状适配会破坏任务关系。该版本结果没有作为正式结果保留。

修正后，v18 将形状对齐目标与原始 R 的任务指尖对目标分开：形状使用 `K_R^L20`，拇食指/拇中指距离使用原始 R 任务目标。修正结果中两组任务对误差分别为 `0.001434` 和 `0.001120`。

## 2. 形状指标的目标发生了变化

v18 的掌部归一化语义点和屈曲角误差是相对 L20 条件化目标计算的，不能直接当作相对自然 MANO 目标的误差。`comparison.json` 明确标记了这一点，避免把目标改变误解为同一任务上的无条件性能提升。

## 3. 仍有时间平滑代价

任务约束与 L20 条件化形状目标同时存在时，当前 smooth_weight=`0.35` 下最大独立 q 单步变化为 `0.979151 rad`。后续需要比较更强平滑、任务对误差和动作延迟，而不是只看单帧形状误差。
