存放约定

  • DataSet/raw/<数据名>/：原始数据，保留来源结构。
  • DataSet/processed/<数据名>/<处理版本>/：转换或清洗后的数据。
  • DataSet/splits/：固定的训练、验证、测试 ID 名单，可用于复现。
  • DataSet/models/：实际获得的模型文件，记录版本与许可。
  • 机器人 URDF 和驱动描述放 robots/，不混入人体数据目录。

一条样本至少包含什么

字段 含义
sample_id、source 唯一 ID 与来源
subject_id 或 shape_id 操作者身份或合成形状，未知时明确标记
sequence_id、frame_id、timestamp 序列、帧与时间，防止相邻帧泄漏
hand_side 左/右手及是否做过镜像
coordinates、units、joint_order 坐标系、单位、关键点/关节顺序版本
landmarks、valid_mask、confidence 关键点与质量信息；不可见与缺失分开记录
mano_beta、mano_pose 可选，记录参数版本、旋转约定和拟合质量
target_geometry_id、robot_id 目标虚拟手几何与机器人
descriptor_version 机构及驱动描述的版本/摘要
reference_pose、actuator_command 可选的阶段一/二参考输出
label_status、residual、solver_config 教师标签质量、优化残差与配置

以上是候选记录契约，不是已经实现的数据加载器。实际格式确定后，在本文件补充一条真实样本和读取命令。

处理与核查顺序

  1. 下载后记录来源 URL、版本、许可证、大小与校验信息。
  2. 随机查看样本并画出编号，检查左右手、坐标与单位。
  3. 去重、清洗、格式转换分别记录脚本及参数；保留原始数据。
  4. 处理镜像时同步修改坐标、旋转与手侧，不能只改标签。
  5. 保存无效帧、优化不收敛、不可达目标的原因与数量，不静默丢掉。
  6. 最后固定划分并冻结指标，记录划分文件摘要；不要依靠目录名猜测是否能训练。

划分草案

人体：按操作者/形状组留出，并保持序列完整。机构：按机器人手型或机构家族留出，写清实际采用的粒度。任务和物体是否留出另行说明。

同一个人的不同视频、同一视频的相邻帧、同一目标手的不同配置不能以样本随机分配来冒充“未见人/未见手”。若确需见过身份的帧级测试，应作为独立条件命名。

比例、实际人数、样本数与机器人名单：待资源盘点后制定。训练、验证、测试 ID 文件尚未创建；不得声称数据集已就绪。
